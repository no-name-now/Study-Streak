The whole course in 30 seconds
In plain English: Think of your body. Skin and eyes sense things (sensors). Nerves carry the signal
(network and gateways). Reflexes react instantly without waiting for the brain (edge computing). The
brain thinks deeply and remembers (cloud). IoT is the whole body working together, and embedded
systems are the tiny "mini-brains" inside each device.

2. What is the Internet of Things (IoT)?
Definition: a network of physical objects ("things") embedded with sensors, software, processing
capability, and communication technology that lets them collect and exchange data over a network.
In plain English: Ordinary objects (a fridge, a car, a watch) that have been given a "sense" (sensor), a
"voice" (internet connection), and a bit of "brain" (software), so they can share information and act on it
without you doing anything.
Simple formula: Physical things + Sensors + Connectivity + Data + Action = IoT
Examples of "things": vehicles, farm equipment, medical devices, wearables, home appliances, security
systems, environmental sensors.

Traditional thermometer:  Temperature → Display → Human reads it
IoT temperature sensor:   Temperature → Sensor → Processing → Network

Gateways
A gateway is a physical device or software program that acts as a secure bridge between local smart
devices and the cloud. It translates different communication "languages" and routes data.
In plain English: A gateway is like a receptionist who also speaks every language: devices tell it things
in their own way, and it passes the message on to the outside world in a way the cloud understands.
5. Cloud computing
Definition: delivery of computing resources (processing power, storage, databases, networking,
software, applications) over a network, usually the Internet.
In plain English: Instead of buying and maintaining a powerful computer, you rent one from a
provider, like renting a car instead of buying one. You pay for what you use.
•
Why we need it: access to massive computing resources without owning them; ability to scale up
and down very quickly; high availability (it is nearly always up).
•
Scaling vertically = make one machine more powerful (a bigger truck).
•
Scaling horizontally = add more machines (more trucks). (my analogy)
6. The two big problems with the cloud: latency and bandwidth
Latency, the delay
Latency is the delay between sending information and receiving a response.
In plain English: The time you wait for an answer. Like shouting to a friend across a field: the further
away, the longer before you hear back.
Example: a self-driving car spots an obstacle. If it must send data to a faraway cloud, wait, and receive a
reply, it could be too late:
Car → Internet → Cloud → Processing → Internet → Car → Brake
Some apps tolerate a few seconds. For others, milliseconds are critical.
Bandwidth, the pipe width
Bandwidth is the maximum rate at which data can be sent over a network connection, usually
measured in bits per second (bps).
In plain English: Think of a water pipe. Bandwidth is how wide the pipe is. Thousands of cameras
sending raw video is like pushing a flood through a garden hose: it jams up (network congestion), costs
more, and sends lots of useless data.
•
Problems: high bandwidth use, increased costs, network congestion, unnecessary data transmission.
•
The big question: do we really need to send everything to the cloud?

7. Edge computing
Definition: a distributed computing model where data processing happens closer to the source of
the data (sensors, devices, local gateways) rather than relying entirely on centralised cloud servers.
In plain English: Do the thinking nearby instead of far away. Like a shop manager who handles small
problems on the spot rather than phoning head office every time.
Traditional cloud: CCTV Camera → Local Network → Internet → Cloud Data Center → Processing
Edge computing:    CCTV Camera → Local Network → Edge Computer → Processing
•
Edge handles immediate processing. Cloud handles long-term storage, analytics, dashboards, and
large-scale processing.
•
The edge is not one specific device. It means computing resources located near the data source:
Raspberry Pi, industrial computer, smart gateway, local server, intelligent camera, vehicle computer.
•
Why it became necessary: data is increasingly produced far from cloud servers, and some apps
need faster, more local processing. Many sensors feed the edge, which analyses locally, detects
problems, and sends only useful information to the cloud.

Learning objectives and "architecture myths"
The objectives slide says the lecture also covers use cases (autonomous vehicles, smart farming,
healthcare: decide the best place to process) and debunks three misconceptions. My plain-English reading
of them (my addition, check with your notes):
•
Myth: everything must go to the cloud. Truth: time-critical decisions are made at the edge.
•

LECTURE 3: Evolution and Architecture of IoT
1. The "Things" in IoT
•
"Things" are devices with unique identities that can do remote sensing, actuating, and
monitoring.
•
They can exchange data with other devices and apps, directly or indirectly, or collect data from other
devices. They can process data locally, send it to servers or the cloud, or split the work. The choice
depends on constraints: memory, processing power, communication delays and speed, and deadlines.
•
An IoT device may have several interfaces, wired and wireless: (i) I/O interfaces for sensors, (ii)
Internet connectivity, (iii) memory and storage, (iv) audio/video.
•
Devices can be wearable sensors, smart watches, LED lights, automobiles, and industrial machines.
Almost all generate data which, when analysed, gives useful information to guide actions locally or
remotely.
2. IoT protocols: the big idea
In plain English: A protocol is just an agreed set of rules for communicating, like etiquette for a phone
call. Sending data across a network is like sending a parcel: several jobs happen in order, and each job

7. Logical design of IoT
The logical design abstracts the system's entities and processes without worrying about low-level
implementation details. It outlines the core components and communication interfaces.
In plain English: Logical design is the architect's floor plan: it shows the rooms and how they connect,
not which bricks or wires are used.
Six IoT functional blocks
Block
Job
Device
Hardware for sensing, actuation, monitoring, and direct control
Communication
Moves data using suitable network standards and protocols
Services
Basic utilities: device discovery, real-time monitoring, control, data publishing
Management
Governance features to manage, configure, and maintain the infrastructure
Security
Keeps the system safe: user authentication, access authorisation, message validation, data
encryption
Application
User interface to monitor status, view analytics, and control devices remotely
In plain English: Authentication = prove who you are (login). Authorisation = what you are allowed
to do. Encryption = scramble data so only the right person can read it.

It starts with a WebSocket handshake: the client sends a connection-setup request over HTTP, which
the server treats as an upgrade request. If supported, the server replies, and then both can send
messages freely.
•
This reduces network traffic and latency (no setup and teardown per message), so it suits IoT apps
needing low latency or high throughput.
10. IoT vs M2M
M2M (Machine-to-Machine) = networking machines or devices for remote monitoring, control,
and data exchange.
•
Often used interchangeably with IoT, but the two terms evolved from different backgrounds.
•
An M2M area network is made of M2M nodes with embedded hardware for sensing, actuation, and
communication.

IPv4's 232 addresses ran out in 2011. IPv6 has 2128.

Running IPv6 on low-power, low-processing devices over 802.15.4.

It is lightweight and publish-subscribe, good for devices with little

Client-Server, Stateless, Cache-able, Layered System, Uniform Interface.
Difference between IoT and M2M?
M2M links machines for remote monitoring and control, often with non-IP
local protocols. IoT is broader and internet-centred. They are often used
interchangeably.
What is an embedded system?
A computer system built into a larger product to do a specific task or
closely related tasks.
MCU vs MPU?
MCU has processor + memory + peripherals on one chip. MPU is the
processor and needs external memory and I/O.
ASIC vs FPGA?
ASIC is custom-made for one job: fast, but costly and fixed. FPGA is

Soft vs hard real-time?
Soft tolerates missed deadlines. Hard can cause catastrophic
consequences if a deadline is missed.
Event-triggered vs time-triggered?
Event-triggered reacts to events. Time-triggered follows a fixed schedule
