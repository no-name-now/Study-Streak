Cloud [Azure] Infrastructure Deployment Key Terminologies
Term
Meaning
Infrastructure provisioning
Creating and configuring resources such as virtual machines, networks, storage and access policies.
Azure subscription
An Azure subscription provides you with authenticated and authorized access to an azure account.
Resource
An individually managed Azure service instance, such as a VM or storage account.
Resource group
A logical container to manage and aggregate resources in a single unit.
Region
A geographic area containing Azure data-centers.
Availability zone
A physically separate location within a supported region designed to improve resilience.
Infrastructure as Code (IaC)
Defining infrastructure in version-controlled, repeatable files instead of relying only on manual actions.
Telemetry
Measurements or events produced by devices and systems, such as temperature or device status.
ARM (Azure Resource Manager)
This provides a management layer that enables you create, update, and delete resources in your azure subscription.

Infrastructure Provisioning on Azure
Gather requirements: workload, capacity, performance, region, security, availability and budget.
Design the architecture: select compute, storage, network, identity and monitoring services.
Organize resources using subscriptions, resource groups, naming conventions and tags.
Define configuration including sizes, network rules, identities, data protection and scaling.
Provision resources through the Azure portal, CLI, PowerShell, ARM templates or Bicep.
Validate connectivity, permissions, health, performance and security.
Operate: monitor, patch, back up, scale, review costs and remove unused resources.

Virtual Machines
A virtual machine (VM) is a software-defined computer that runs an operating system and applications on virtualized hardware. Azure Virtual Machines provide Infrastructure as a Service (IaaS) when an organization needs operating-system-level control, custom software or a migration path with minimal architectural change.
VM Design Decisions
Operating system: select a supported Windows or Linux image.
Size: choose CPU, memory, storage throughput and network capacity based on measured workload.
Disks: distinguish OS, temporary and persistent data disks; plan backup and recovery.
Networking: use suitable virtual networks and subnets and restrict inbound access.
Identity: prefer managed identities where supported; avoid embedding credentials in scripts.
Availability: consider zones, availability sets or scale sets as appropriate.
Operations: plan patching, monitoring, backups, recovery objectives and cost controls.

Scalability and Elasticity
Scalability is the ability to handle increased workload by adding resources or improving capacity. Elasticity is the ability to adjust resources as demand changes, including scaling down when demand falls. A system can scale without being elastic if capacity is increased manually and never reduced automatically.

When to Use a VM
VMs are useful when software requires a specific operating system, custom system packages, administrative control or legacy compatibility. They create operational responsibilities: teams must manage OS updates, runtime configuration, security, capacity and recovery.
VM Security Checklist
Avoid exposing SSH or RDP broadly to the internet.
Use controlled administrative access, strong authentication and least privilege.
Apply operating-system and application security updates.
Use Network Security Groups and network segmentation.
Enable logging, monitoring, backup and alerting.
Store secrets in a dedicated secret-management service rather than source code.

Containers and Container-Based Deployment
A container packages an application with its runtime dependencies and configuration into an image. Containers share the host operating-system kernel, making them generally lighter and faster to start than full virtual machines. A VM virtualizes a complete operating-system environment; a container isolates application processes.
