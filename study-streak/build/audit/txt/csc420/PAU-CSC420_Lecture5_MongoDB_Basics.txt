What Is MongoDB?
MongoDB is a document database: it stores data as 
JSON-like documents instead of rows in tables.
A document can hold nested objects and arrays, so 
related data can live together in one record.
Documents in the same collection do not need the 
same fields: the schema is flexible.
It is built to scale out across many servers.
Industry relevance: flexible storage for e-commerce 
product catalogues, where every product type has 
different details.

From Tables to Documents
Table → collection
Row → document
Column → field
Primary key → the _id field: every document has 
one, unique within its collection.
CREATE TABLE → nothing: a collection is created the 
first time you insert into it.
JOIN → usually not needed: related data is
embedded in one document or referenced by its _id.

Documents Are Stored as BSON
MongoDB stores documents as BSON: a binary form 
of JSON with extra types, such as Date and ObjectId.
If a document has no _id, one is generated 
automatically as an ObjectId.
A single document can be at most 16 MiB.
Fields inside embedded documents are reached with 
dot notation, e.g. "address.city".
Compare Lecture 2: a JSONB column holds one 
document in a table; in MongoDB, the whole record 
is the document.

MongoDB Architecture
mongod is the database server. It listens on port 27017 by 
default.
Clients connect with a connection string, e.g. 
mongodb://localhost:27017:
▪ mongosh, the MongoDB Shell; Compass, the graphical tool; and 
drivers for Python, Java, Node.js, …
One server holds many databases; a database holds 
collections; a collection holds documents.
At scale, replica sets keep copies of the data on several 
servers, and sharding spreads a collection across servers.

Installing MongoDB Locally 
(Windows)

Reading Documents
The filter is itself a document: 
{ field: value }.
findOne returns the first match; find returns all 
matches. An empty filter {} matches everything.
db.products.findOne({ _id: 8 })
db.products.find({ product_type: "digital" })

Practical 3

Projection: Choosing 
Fields
The second argument picks the fields to return: 1 
includes, 0 excludes. _id is returned unless you 
exclude it.
In SQL: SELECT name, tags FROM products WHERE 
product_type = 'digital';
db.products.find(
  { product_type: "digital" },
  { name: 1, tags: 1, _id: 0 })

Practical 6

Updating Documents
The first argument finds the document; the second 
says what to change.
$set sets a field, even a nested one; $push adds an 
element to an array. Kemi moves to Abuja and adds a 
number.
db.users.updateOne(
  { _id: 11 },
  { $set: { "address.city": "Abuja" },
$push: { mobiles: "+2349034567812" } })

Deleting Documents
countDocuments returns 0: Chi Limited makes 
no products, so it is safe to delete.
MongoDB has no foreign keys: it would delete SC 
Johnson (_id: 1) too, though products still refer to 
it. Your application must check first.
db.products.countDocuments({ manufacturer_id: 13 })
db.manufacturers.deleteOne({ _id: 13 })

SCHEMA DESIGN
Embedded vs referenced data
Dr. Stephen A. Adubi 23

Two Ways to Relate Data
Embedded: related data is stored inside the 
document.
▪ a product's variations and their attributes; a user's 
address.
Referenced: a document stores another document's 
_id.
▪ a product's manufacturer_id; an order's user_id.
This is why seven tables became four collections: 
variations and attribute_catalogue are now inside 
products, and tags are plain strings.

Embedded: One Read
One query returns the product with all its 
variations. In PostgreSQL, this needed a JOIN.
A write to one document is all-or-nothing, so a 
product and its variations change together.
db.products.findOne(
  { _id: 1 },
  { name: 1, variations: 1 })

Referenced: Two Reads
The order stores only user_id, so finding the 
customer takes a second query.
const keeps the first result in a shell variable.
const order = db.orders.findOne(
                { _id: "20260112093015_1" })
db.users.findOne({ _id: order.user_id },
                 { first_name: 1, last_name: 1 })

Embed or Reference?
Embed when the data belongs to one parent and is 
read or updated with it, e.g. variations, an address.
Reference when the data is shared by many 
documents, can exist on its own, or would grow 
without limit, e.g. manufacturers, a user's orders.
Remember the 16 MiB limit: embedding every order 
inside its user would keep growing that document.
Copies of shared data that change often are hard to 
keep in step; reference them instead.

Wrap
-
Up: Key Takeaways
MongoDB stores BSON documents in collections; 
every document has a unique _id, and the schema is 
flexible.
mongod is the server; mongosh, Compass and drivers 
connect to it with a connection string.
CRUD: insertOne/insertMany, find/findOne with a 
filter and projection, updateOne with $set or $push, 
and deleteOne.
Schema design: embed what belongs together; 
reference what is shared or grows without limit.
