Why Put Logic in the Database?
Constraints check one row at a time. Many business 
rules need more:
▪ looking at other rows or tables, e.g. a tag must exist;
▪ computing values, e.g. an order total;
▪ running several steps as one unit, e.g. place an order and 
reduce stock.
PostgreSQL can store such logic inside the database 
as functions, procedures and triggers.
Every application using the database then follows the
same rules.
Dr. Stephen A. Adubi

Functions, Procedures & Triggers 
(Comparison)
Function — takes inputs and returns a value (or a table); 
used inside SQL, e.g. SELECT fn(…).
Procedure — performs an action and returns no value; run 
with CALL; may COMMIT or ROLLBACK partway through.
Trigger — runs automatically when rows are inserted, 
updated or deleted; its body is a function that RETURNS 
TRIGGER.
Functions and procedures can be written in plain SQL or in 
PL/pgSQL, PostgreSQL's procedural language. Trigger 
functions need PL/pgSQL (or another procedural language).

From SQL to PL/pgSQL
A SQL function runs queries only: no variables, no IF, 
no loops.
PL/pgSQL adds programming constructs:
▪ DECLARE variables and assign them with :=;
▪ SELECT … INTO a variable;
▪ IF … ELSIF … ELSE … END IF and FOR … LOOP … 
END LOOP;
▪ RAISE EXCEPTION to stop with an error, RAISE NOTICE 
to print a message;
▪ FOUND, which is true when the last statement found or 
changed a row.

Our First Function
The function returns the total sum of all items in an order: here, 
the sum of 𝑢𝑛𝑖𝑡_𝑝𝑟𝑖𝑐𝑒 ×  𝑞𝑢𝑎𝑛𝑡𝑖𝑡𝑦.
CREATE FUNCTION fn_order_total(p_items JSONB) RETURNS NUMERIC
LANGUAGE plpgsql AS $$
DECLARE
  total_amount numeric;
BEGIN
  SELECT sum((i ->> 'unit_price')::numeric
                      * (i ->> 'quantity')::int) INTO total_amount
  FROM jsonb_array_elements(p_items) AS i;
  RETURN total_amount;
END
$$;

Functions vs Procedures
A procedure is created with CREATE PROCEDURE 
and run with CALL, not SELECT.
It returns no value. Use a procedure to do something 
(a business operation); use a function to compute 
something.
If any step of a CALL fails, every change it made is
undone: atomicity from Lecture 1.
A procedure may also COMMIT or ROLLBACK part-
way through (when not called inside an explicit 
transaction). A function never can.

What Is a Trigger?
A trigger makes Postgres run a trigger function 
automatically when a table changes.
Each trigger is defined by its:
▪ event: INSERT, UPDATE, DELETE (or TRUNCATE);
▪ timing: BEFORE or AFTER the change;
▪ level: FOR EACH ROW (once per row) or FOR EACH 
STATEMENT (once per statement).
It is created in two steps: a function that RETURNS 
TRIGGER, then CREATE TRIGGER … EXECUTE 
FUNCTION.
Dr. Stephen A. Adubi

NEW, OLD & BEFORE vs AFTER
Inside a row-level trigger function:
▪ NEW is the new row (INSERT, UPDATE); OLD is the old row 
(UPDATE, DELETE);
▪ TG_OP holds 'INSERT', 'UPDATE' or 'DELETE'; 
TG_TABLE_NAME holds the table's name.
BEFORE triggers can change the row by changing 
NEW and returning it, or skip the row by returning 
NULL. Use them to fill in or check values.
AFTER triggers run once the row is saved, and their 
return value is ignored. Use them to react, e.g. write 
an audit log.

Keeping the Total 
Correct (1)
The function overwrites NEW.total_amount and returns the 
row.
RETURNS, LANGUAGE and AS can share one line, as here.
CREATE FUNCTION trg_fn_order_total()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
NEW.total_amount := fn_order_total(NEW.items);
  RETURN NEW;
END;
$$;

Dos and Don’ts
Do prefer constraints (NOT NULL, CHECK, FOREIGN KEY) 
whenever they can express a rule.
Do use triggers only for rules that constraints cannot 
express.
Do keep trigger functions short and clearly named (e.g. 
trg_fn_…).
Don’t hide surprising behaviour in triggers; others may not 
know they exist.
Don’t forget the cost: a row-level trigger runs for every row, 
slowing bulk loads.
Beware of triggers that fire other triggers: they can 
cascade.

Choosing the Right Tool
Compute a value to reuse in queries → a function 
(e.g. fn_order_total).
Carry out a multi-step operation, all or nothing → a 
procedure (e.g. sp_place_order).
Fill in or check data automatically, whoever changes 
it → a BEFORE trigger (e.g. trg_order_total).
React to changes, e.g. keep a history → an AFTER 
trigger (e.g. an audit log).
Check a single row's own values → a CHECK 
constraint; no code needed.

Wrap
-
Up: Key Takeaways
Functions return a value or a table and are used 
inside SQL. SQL functions run queries; PL/pgSQL adds 
variables, IF, loops and RAISE.
Procedures are run with CALL and undo all their work 
if any step fails.
Triggers run a function automatically: BEFORE triggers 
fill in or check NEW; AFTER triggers react to changes.
Together they enforced rules Lecture 2 could not: 
order totals, order IDs and stock levels.
